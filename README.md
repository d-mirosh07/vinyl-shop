# **Vinyl Shop**

## **Опис**

Vinyl Shop - інтернет-магазин для любителів та поціновувачів музики на вінілі.

Користувач може переглядати каталог платівок.
На сторінці платівки видно ціну, наявність, список пісень і відгуки.

Гості (неавторизовані користувачі) мають доступ лише до читання каталогу, списку виконавців і жанрів.Під час спроби додати платівку до бажаного або перейти до захищеного розділу неавторизованого користувача перенаправляє на реєстрацію чи логін з інформаційним повідомленням.

Авторизовані користувачі отримують доступ до власного списку бажаного (Wishlist) з можливістю додавати платівки та видаляти їх.

## Як запустити проєкт
1. Створити й увімкнути віртуальне середовище:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```
2. Встановити залежності:
   ```bash
   pip install -r requirements.txt
   ```
3. Виконати міграції:
   ```bash
   python manage.py migrate
   ```
4. Запустити сервер:
   ```bash
   python manage.py runserver
   ```

Бекенд працює на `http://127.0.0.1:8000/`. Усі адреси API починаються з `/api/` і закінчуються `/`.
Фронтенд (окремий репозиторій `vinyl-shop-frontend`) працює на `http://localhost:63342`.

## API

Усі дані передаються у форматі JSON.

## Авторизація
### Як передавати токен

Для захищених ендпоінтів потрібен access-токен у заголовку:
```
Authorization: Bearer <access токен>
```
Запит без токена повертає 401:
```json
{ "detail": "Authentication credentials were not provided." }
```
Прострочений або недійсний токен також повертає 401:
```json
{
  "detail": "Given token not valid for any token type",
  "code": "token_not_valid",
  "messages": [
    {
      "token_class": "AccessToken",
      "token_type": "access",
      "message": "Token is expired"
    }
  ]
}
```
### POST /auth/register/ - 201
Реєстрація нового користувача. Токен не потрібен. Пароль зберігається лише у вигляді хешу.

| Поле | Обов'язкове | Обмеження |
|---|---|---|
| `username` | так | до 150 символів, унікальний |
| `email` | так | коректний формат, до 254 символів, унікальний |
| `first_name` | ні | до 50 символів |
| `last_name` | ні | до 50 символів |
| `password` | так | від 8 до 128 символів, не лише цифри, не надто поширений |
| `password2` | так | має збігатися з `password` |

**Тіло запиту:**
```json
{
  "username": "daria",
  "email": "daria@example.com",
  "first_name": "Daria",
  "last_name": "K",
  "password": "Capybara2026",
  "password2": "Capybara2026"
}
```
**Відповідь 201:**
```json
{
  "id": 1,
  "username": "daria",
  "first_name": "Daria",
  "last_name": "K",
  "email": "daria@example.com"
}
```
**Відповідь 400** (помилка для кожного невалідного поля):
```json
{
  "username": ["This field may not be blank."],
  "email": ["Enter a valid email address."],
  "password": ["Ensure this field has at least 8 characters."]
}
```
Слабкий пароль:
```json
{ "password": ["This password is too common.", "This password is entirely numeric."] }
```
Паролі не збігаються:
```json
{ "password2": ["Паролі не збігаються."] }
```
Зайнятий email:
```json
{ "email": ["Користувач з таким email вже існує."] }
```

### POST /auth/login/ - 200
Вхід за `username` і паролем. Токен не потрібен.
**Тіло запиту:**
```json
{ "username": "daria", "password": "Capybara2026" }
```
**Відповідь 200:**
```json
{ "refresh": "<refresh токен>", "access": "<access токен>" }
```
**Відповідь 401** (неправильні дані):
```json
{ "detail": "No active account found with the given credentials" }
```

### POST /auth/refresh/ - 200
Оновлює access-токен. Access живе 10 хвилин, refresh живе 1 день. Коли access закінчується (запит повертає 401 з кодом `token_not_valid`), клієнт надсилає refresh на цей ендпоінт і отримує новий access, не змушуючи користувача входити знову. Якщо refresh теж прострочений, потрібно увійти заново. Токен у заголовку не потрібен.
**Тіло запиту:**
```json
{ "refresh": "<refresh токен>" }
```
**Відповідь 200:**
```json
{ "access": "<новий access токен>" }
```
**Відповідь 401** (refresh недійсний або прострочений):
```json
{ "detail": "Token is invalid or expired", "code": "token_not_valid" }
```

### Logout
Окремого ендпоінта немає: при виході клієнт видаляє збережені access і refresh токени.

## Платівки
### GET /albums/ - 200
Список платівок. Доступний без токена.

**Параметри (необов'язкові):** `search` (текст у назві), `artist_id`, `genre_id`. Параметри можна поєднувати, наприклад `/api/albums/?artist_id=1&search=thr`.
```json
[
  { "id": 1, "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
]
```
### GET /albums/{id}/ - 200
Одна платівка. Доступна без токена. Якщо платівки немає, повертається 404 `{ "error": "Платівку не знайдено" }`.
```json
{ "id": 1, "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
```
### POST /albums/ - 201
Додає платівку. Потрібен токен, без нього 401. Неправильні дані дають 400 з помилками по полях.
**Тіло запиту:**
```json
{ "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
```
**Відповідь:**
```json
{ "id": 1, "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
```
### PATCH /albums/{id}/ - 200
Змінює дані платівки, наприклад ціну чи наявність. Потрібен токен, без нього 401. Якщо платівки немає, повертається 404.
**Тіло запиту** (необов'язкові поля: `title`, `price`, `in_stock`, `artist`, `genre`):
```json
{ "price": "799.00", "in_stock": false }
```
**Відповідь:**
```json
{ "id": 1, "title": "Thriller", "price": "799.00", "in_stock": false, "artist": 1, "genre": 1 }
```
### DELETE /albums/{id}/ - 204
Видаляє платівку. Потрібен токен, без нього 401. Якщо платівки немає, повертається 404. Відповіді немає.

## Виконавці
### GET /artists/ - 200
Список виконавців. Доступний без токена.
```json
[
  { "id": 1, "name": "Michael Jackson" }
]
```
### GET /artists/{id}/ - 200
Один виконавець. Доступний без токена , якщо його немає, повертається 404.
```json
{ "id": 1, "name": "Michael Jackson" }
```
### POST /artists/ - 201
Додає виконавця. Потрібен токен, без нього 401.
**Тіло запиту:**
```json
{ "name": "Michael Jackson" }
```
**Відповідь:**
```json
{ "id": 1, "name": "Michael Jackson" }
```
### PATCH /artists/{id}/ - 200
Змінює виконавця. Потрібен токен, без нього 401. Якщо його немає, повертається 404.
**Тіло запиту** (необов'язкове поле: `name`):
```json
{ "name": "Michael J. Jackson" }
```
**Відповідь:**
```json
{ "id": 1, "name": "Michael J. Jackson" }
```
### DELETE /artists/{id}/ - 204
Видаляє виконавця. Потрібен токен, без нього 401. Відповіді немає. Якщо виконавця немає, повертається 404. Якщо в нього є платівки, повертається 409 `{ "error": "Неможливо видалити виконавця, у нього є платівки" }`.

## Бажане
Список бажаного доступний лише авторизованим користувачам, кожен бачить і змінює лише свій список. Усі запити потребують заголовок `Authorization: Bearer <access токен>`, без нього 401.

### GET /wishlist/ - 200
Платівки зі списку бажаного поточного користувача.
```json
[
  { "id": 1, "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
]
```
### POST /wishlist/ - 201
Додає платівку в бажане. Повторне додавання тієї самої платівки дублікатів не створює. Якщо платівки немає, повертається 404 `{ "error": "Платівку не знайдено" }`.
**Тіло запиту:**
```json
{ "album": 1 }
```
**Відповідь:**
```json
{ "id": 1, "title": "Thriller", "price": "899.00", "in_stock": true, "artist": 1, "genre": 1 }
```
### DELETE /wishlist/{id}/ - 204
Прибирає платівку зі списку бажаного. `{id}` це номер платівки, а не номер запису у списку. Відповіді немає. Якщо платівки немає у списку, повертається 404 `{ "error": "Платівки немає у списку бажаного" }`.
